# 多模型解题：补充陷阱与经验（v2 增量）

本 skill 是 `multi-model-math-solving` 的补充，记录实战中发现的新陷阱。主流程仍遵循原 skill。

## 触发条件
与 `multi-model-math-solving` 相同：用户提供数学题要求解答时。加载原 skill 后也加载本 skill。

## 新增步骤：模型分歧时必做手动 spot-check

当两个模型给出不同答案时，在依赖 verify_analysis 之外，**必须**手动代入具体数值验证分歧点：
1. 找到两个模型答案的差异区间（如"a<-2 时零点个数"）
2. 取该区间内一个具体值（如 a=-3）
3. 手动代入原函数计算 f(候选零点)，验证是否确实为零
4. 同时检查候选零点是否满足所在分段的域条件
5. 如有 Python 环境则用代码批量验证；无 Python 时手算即可，几步四则运算足够

## 新增陷阱

### Gemma 分段函数域检查易错
Gemma 在处理含绝对值的分段函数时，容易忽略"候选根是否落在对应分段的有效域内"。典型场景：当参数使 g(x) 的判别式 > 0 导致 g(x) 变号时，Gemma 可能仍按 g(x) 恒正/恒负的简单情况处理，漏掉域检查。遇到分段函数/绝对值题且 Gemma 与 DeepSeek 分歧时，优先手动代入具体参数值验证 Gemma 的候选根是否真的满足所在分段的条件。

### verify_analysis 对域检查的局限性
`verify_analysis` (Qwen) 对纯代数计算的校验较可靠，但对"候选根是否在正确的分段域内"这类条件验证能力有限——实测中曾出现将错误的域判断标记为 `right` 的情况。具体案例：Gemma 声称 a<-2 时 x=1/(a-1) 和 x=1/(a+1) 分别来自情况A和情况B各贡献1个零点共2个，verify_analysis 判定该步骤正确，但手动代入 a=-3 后发现 x=1/(a-1)=-1/4 虽然满足 g(x)≥0 但代入 h₁ 方程后 f 值为零是对的，而 x=-1 作为 h₁ 的另一个根却不满足 g(-1)≥0（因为 g(-1)=1+3+1=5>0... 实际上需要更仔细地检查每个根在每个分段的归属）。关键教训：当模型分歧涉及分段域归属问题时，不要仅依赖 verify_analysis，必须手动代入具体数值做 spot-check。

### 无 Python 环境时的数值验证替代方案
当环境中没有 Python 可用时，手动代入特定参数值进行代数验算同样有效。关键技巧：
- 选取使计算简单的整数或简单分数值
- 同时验证两件事：(1) f(候选根) 是否为 0；(2) 候选根是否在正确的分段域内
- 如果某个模型声称某区间有 N 个零点，取该区间内一个具体参数值全面检查
